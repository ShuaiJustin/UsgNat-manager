# 需求文档生成

## 核心

把模糊意图推进成可落地的产品需求文档。不要静默猜测；持续追问，直到用户、问题、范围和验收标准可验证。

## 输入

- 用户的想法或变更请求。
- 已存在的 `Product-Spec.md` 和变更记录。
- 可用的现有产品、设计或代码上下文。

## 产出

- 更新后的 `Product-Spec.md`。
- 首版后的变更写入 `Product-Spec-CHANGELOG.md`。
- 阻塞实现的开放问题。

## 规则

- 第一版范围要窄。
- 明确写出不在范围内的内容。
- 每个 P0 需求都需要可观察的验收标准。
- 目标用户或核心问题仍模糊时，不解锁实现。

## 检查清单

- [ ] 目标用户具体。
- [ ] 用户问题具体。
- [ ] 第一版范围小。
- [ ] 需求已编号。
- [ ] 验收标准可验证。
