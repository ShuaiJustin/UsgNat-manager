# 缺陷修复

## 核心

修缺陷靠证据，不靠猜。一次形成少量假设，逐个验证，只改证据支持的地方。

## 输入

- 错误输出、复现步骤、截图、日志或失败测试。
- 相关代码和最近变更。
- 文档中定义的预期行为。

## 产出

- 根因摘要。
- 最小修复。
- 验证证据。

## 规则

- 改代码前必须复现或检查证据。
- 记录被否定的假设，避免重复验证。
- 尽量一次只改一个原因。
- 连续三次修复失败后停止，重新检查问题前提。

## 检查清单

- [ ] 已捕捉证据。
- [ ] 已说明根因。
- [ ] 修复足够小。
- [ ] 已运行回归检查。
