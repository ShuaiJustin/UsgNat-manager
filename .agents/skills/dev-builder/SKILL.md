# 开发执行

## 核心

只实现当前限定任务。编辑前重读相关文档，然后按明确完成标准推进。

## 输入

- 当前 `DEV-PLAN.md` 阶段或任务。
- `Product-Spec.md`。
- 相关的 `Design-Brief.md` 和设计产物。
- 现有代码库。

## 产出

- 代码变更。
- 当需求或设计变化时，同步文档更新。
- 验证证据。

## 规则

- 删除或重命名共享代码前先全局搜索。
- 优先复用已有组件、样式、工具函数和接口。
- 不做假按钮、假数据或装饰性不可用界面。
- 没有当前验证输出，不得宣称完成。

## 检查清单

### 基础检查
- [ ] 已重读相关文档。
- [ ] 范围匹配当前任务。
- [ ] 合理复用了现有模式。
- [ ] 已包含验证命令输出。

### SOLID原则快速检查

**单一职责原则 (S)**
- [ ] 每个新增类/模块职责单一明确
- [ ] 类名准确反映其唯一职责

**开闭原则 (O)**
- [ ] 新功能通过扩展实现而非修改现有代码
- [ ] 依赖抽象接口而非具体实现

**里氏代换原则 (L)**
- [ ] 子类可以安全替换父类
- [ ] 没有违反父类契约

**接口隔离原则 (I)**
- [ ] 接口设计足够小且专注
- [ ] 没有强迫类实现不需要的方法

**依赖倒置原则 (D)**
- [ ] 高层模块不直接依赖低层模块
- [ ] 使用了依赖注入或接口抽象
