# 开发计划

## 核心

把已确认的需求转成可分阶段执行的开发计划。每个阶段必须能编译、能运行，并产生可见进展。

## 输入

- `Product-Spec.md`。
- `Design-Brief.md` 和已有设计产物。
- 现有项目结构和约束。

## 产出

- 更新后的 `DEV-PLAN.md`。
- 阶段顺序、交付物、验证命令和风险说明。

## 规则

- 基础设施和依赖项先做。
- 高风险工作尽量前置。
- 避免“稍后”“待定”和模糊任务。
- 每个任务都要让不了解历史对话的人也能开工。

## 检查清单

- [ ] 阶段按依赖排序。
- [ ] 每个阶段都有交付物。
- [ ] 每个阶段都有验证命令。
- [ ] 风险清楚可见。
